# 提醒事项（待办）

在输入框里以 **`#todo`** 开头写一句话，回车即创建系统「提醒事项」：

```
#todo 明天下午三点提醒我给张工回电话
```

前缀默认是 `#todo`，可在「设置 → 提醒事项」里改或关闭。

## 三步链路

| 步骤 | 说明 |
|------|------|
| 抽取 | 用当前配置的模型做**一次非流式调用**（关闭思考），把自然语言抽成结构化字段（标题 / 截止 / 时刻 / 提前提醒 / 重复 / 优先级 / 备注） |
| 确认 | 面板内弹出确认卡，标题、日期、时刻、重复、优先级、目标清单都可改；**确认后才写入** |
| 写入 | 经 EventKit 写入系统「提醒事项」，成功后给出可撤销的提示条 |

抽取链路不依赖 EventKit（`TodoParser` 纯逻辑 + `TodoDraft` 数据载体），因此可以在无头环境下完整断言。

## 实测抽取效果

基准时间 2026-09-14 17:45（周一），`deepseek-flash`，每句抽取耗时均 < 1.2s：

| 输入 | 抽取结果 |
|------|----------|
| 明天下午三点提醒我给张工回电话 | 标题=给张工回电话 · 截止 09-15 · 时刻 15:00 |
| 下周一之前把季度报表交了，提前一天提醒我 | 截止 09-21 · 提前 1440 分钟 |
| 每天早上八点提醒我吃降压药 | 重复=每天 · 时刻 08:00 · 截止=次日 |
| 这周五前回复梅帅鹏的邮件，重要 | 截止 09-18 · 优先级=高 |
| 买牛奶 | 仅标题，**不编造任何时间字段** |

## 几条刻意定死的规则

- **只有日期、没有时刻 = 全天提醒**。此时不写入闹铃，由「提醒事项 → 默认提醒时间」决定何时响（`alarmDate = nil`）。硬塞 00:00 会让提醒时间凭空变成午夜。
- **绝不产出已经错过的提醒**。17:45 说「三点开会」，模型可能填成今天 15:00 —— 这类「日期是今天、时刻已过」的结果会被自动顺延一天（你说的「三点」必然是下一个三点）。**往期日期不参与顺延**。这条是不变量，自检里有专门断言。
- **拿不准就留空**。提示词明确要求不编造日期；抽不出时间时只留标题，剩下的在确认卡上补。
- **`priority` 映射到 `EKReminder.priority`**（1 最高、9 最低、5 为中、0 为无），界面上的「优先级」下拉直接对应这四档 —— 它表达的是优先级，不是「重要」。
- **重复规则原生支持**（每天 / 每周 / 每月 / 每年），写入 `EKRecurrenceRule`。
- **前缀匹配有词边界**：`#todoist` 不命中，但 `#todo买牛奶` 必须命中。

## 存为待办

每条 AI 回答下方有「存为待办」。点击后模型**只负责压缩出一个动作导向的标题**，回答原文由程序直接写进备注、原问题写进来源 —— 长文不让模型转述，避免被截断或改写。可在「设置 → 提醒事项」里关掉这个按钮。

## 权限与边界

- 「设置 → 提醒事项」可查看授权状态、请求授权、跳转系统设置、选择默认清单。
- 首次使用弹出系统授权框。**若被拒绝，必须到「系统设置 → 隐私与安全性 → 提醒事项」手动放开**。
- 缺少稳定代码签名时，**每次重新编译都要重新授权**（原因见 [code-signing.md](code-signing.md)）。
- 只能写入本机「提醒事项」（含 iCloud 账号下已同步的清单）。它与 Microsoft To Do 是**两套互不相通的存储** —— 写进提醒事项的任务不会出现在 To Do 里。
- 清单解析会过滤 `allowsContentModifications == false` 的清单，避免选中只读清单后写入静默失败（只读清单的标记见 `RemindersStore.resolveCalendar`）。
