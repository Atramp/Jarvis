# 思考模式与参数

「设置…」→ **思考模式（Thinking）**。所有字段严格对齐 DeepSeek 官方文档（`guides/thinking_mode` 与 `api/create-chat-completion` 现行版本）。

| 配置项 | 默认 | 说明 |
|--------|------|------|
| 启用思考模式 | **开启** | 对应请求体 `thinking: {"type": "enabled"}`（关闭则 `disabled`）。官方默认即为开启 |
| 思考强度 | **high** | 对应 `reasoning_effort`，可选 `low / high / max`。官方默认档为 `high` |
| max_tokens | **0（不发送）** | 留 0 表示不发送该字段，完全跟随服务端额度；需要收窄时才填值（合法区间 1 ~ 393216） |
| 采样温度 | 0.2 | **仅非思考模式下会随请求发送**。思考模式下该参数不生效，故不发送 |

思考模式开关是**会话级**的 —— 问答窗口内按 `⌘T` 可对当轮临时切换，面板关闭后回落到设置页的默认值。若 Base URL 非 DeepSeek，面板内的开关会置灰并给出说明，不会静默失效。

## 界面为什么不显示思考过程

自适应思考模型（默认的 `deepseek-flash`）在回答难题前会先「想一遍」，这部分内容以 `reasoning_content` 字段单独推送。**本工具不把它渲染到界面**（2026-09-21 产品决定）：

- 思考模式只影响 API 行为（答案质量与首字耗时），回答只呈现最终正文；
- 等待期间由**窗口边缘流光** + 一行状态文字统一指示加载状态。

数据结构上 `ChatMessage.reasoning` 仍会采集（便于将来做开关），但 `ContentView` 不渲染它。

**实现要点**

- 思考过程**不会**回填进后续请求的 `messages` —— DeepSeek 要求不要把 `reasoning_content` 当作历史消息回传，否则会污染多轮上下文（未携带 `tools` 参数的请求即使回传也会被服务端忽略）。
- 思考 token 同样占用输出额度。本工具**默认不发送 `max_tokens`**，由服务端决定额度（思考模式默认 64K，强度 `max` 时 128K），不会因人为设限出现「思考消耗殆尽、回答为空」。

## 为什么有些参数被去掉了

早期版本固定发送 `temperature: 0.2`、`top_p: 0.9`、`presence_penalty: 0.0`、`frequency_penalty: 0.0`。按官方文档现行说明，这四个参数在默认的思考模式下**全部无效**：

- `temperature`、`frequency_penalty`、`presence_penalty` 在思考模式下不生效（后两者官方已标注 **deprecated**，传入不产生任何效果）；
- `top_p` 虽在思考模式下生效，但**小于 0.95 的值会被抬升至 0.95**（原设的 0.9 等于没写）；非思考模式下该参数恒为 1.0，传入值被忽略。

因此现在按模式**只发送真正生效的参数**（纯函数 `LLMClient.makeRequestBody`，四种组合都有断言覆盖），避免给使用者造成「调了它」的错觉。想换风格请改系统提示词，而不是采样参数。

## 实测：什么在真正决定「回答有多详细」

同一问题（CAP 定理 + 举例）在 `deepseek-flash` 上的实测：

| 配置 | 思考字数 | 回答字数 | 耗时 |
|------|---------|---------|------|
| 通用问答人设 · 思考 high | 6900 | 880 | 26.1s |
| **详尽解读人设 · 思考 high** | 14149 | **2978** | 59.4s |
| 详尽解读人设 · 关闭思考 | 0 | 3092 | 14.7s |

结论有点反直觉，但很重要：

- **决定回答长度的是系统提示词，不是思考强度。** 换成「详尽解读」人设后回答从 880 字涨到 2978 字（约 3.4 倍）。
- **提高思考强度增加的是「想得更深」，不是「答得更长」。** 另一组同题实测中，`low / high / max` 三档的思考量单调递增（4017 / 7852 / 14183 字），但回答字数并未随之增长（1099 / 1133 / 947 字）。
- 关闭思考后回答反而最长（3092 字）且最快（14.7s）—— 模型不再分出一部分预算去做内部推理。

因此按目标选配置：

| 你要的是 | 怎么配 |
|---------|-------|
| 回答更长、更详尽 | 系统提示词选「详尽解读」预设；`max_tokens` 保持 0 |
| 难题推理更可靠 | 开启思考，强度 `high` 或 `max` |
| 日常问答要快 | 关闭思考（`⌘T`） |
| 一律不截断 | `max_tokens` 保持 0（默认即如此） |

> 注：以上为单题单次实测，用于说明各杠杆的相对量级，不是统计结论。

## 与其他服务商的兼容

`thinking` / `reasoning_effort` 是 DeepSeek 私有扩展字段。本工具按 Base URL 判断端点（`Config.isDeepSeekEndpoint`），**仅当域名是 `deepseek.com` 时才发送这两个字段**；换成通义千问 / Kimi / OpenAI 时自动跳过，避免严格校验未知字段的服务商直接返回 400（此时温度参数照常发送，非思考模型的行为不受影响）。
