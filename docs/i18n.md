# 界面语言（i18n）

## 结论先行

- 两套文案：**简体中文 / English**。默认「跟随系统」，设置 → 通用 → 语言可切，**切换立即生效，无需重启**。
- 译文**不是** `.lproj/Localizable.strings`，而是 Swift 代码里的两张表：`L10n.swift` 管界面文案，`Prompts.swift` 管发给模型的文本。
- 覆盖率靠 `./tools/selftest.sh` 断言（63 条 i18n 断言），不靠人眼。

## 为什么不用 `.lproj/Localizable.strings`

| 方案 | 在本工程的表现 |
|---|---|
| `.lproj` + `NSLocalizedString` | 要把 `.lproj` 目录塞进 `.app` 并在 Makefile 接线；`make run`（裸二进制）或把可执行文件单独拷走时 `Bundle.main` 里没有资源，`NSLocalizedString` 会**静默退化成显示 key**；运行时切语言要重载 Bundle 或重启进程 |
| **Swift 表（当前选择）** | 直编产物自带全部译文，两种跑法行为一致；切语言只改一个 `@Published` 值；可用 `Key.allCases` 穷举断言覆盖率和占位符一致性 |

代价：交给外部翻译时要从表里导出；语言数量涨到 4~5 种以上时，`.lproj` / String Catalog 的收益会反超。到那时再迁移也不难 —— `L10n.t()` 是唯一的取值入口，迁移面收得住。

## 语言怎么定

`AppLanguage`（用户选择，落盘在 `Config.appLanguage`）：

| 取值 | 含义 |
|---|---|
| `system` | 跟随系统（默认） |
| `zh-Hans` | 简体中文 |
| `en` | English |

`ResolvedLanguage.resolve(_:preferred:)` 把选择解析成实际生效语言。规则是纯函数（偏好列表可注入，便于无头断言）：

1. 选了 `zh-Hans` / `en` → 直接用，不看系统。
2. 选了 `system` → **按顺序**扫描 `Locale.preferredLanguages`（不是只看第一条 —— 装了 `[fr, en]` 的机器应当拿到英文）：
   - 任何 `zh*` → 简体中文。`zh-Hant` / `zh-TW` / `zh-HK` 也归到这里：没有繁体译文表，而繁体读者读简体的成本远低于读英文。
   - 任何 `en*` → English。
3. 都不是（纯日语 / 德语系统）或偏好列表为空 → 简体中文，与 `Info.plist` 的 `CFBundleDevelopmentRegion` 一致。

运行中系统语言被改动 → `NSLocale.currentLocaleDidChangeNotification` → 重新解析（只对 `system` 有意义）。

## 什么被本地化了

**已本地化**

- 全部界面文案：菜单栏菜单项、设置页每个分区与说明、面板输入栏 / 按钮 / 悬浮提示、待办确认卡、等待与占位文案、错误提示（LLM / 搜索 / 提醒事项）、内置浏览器加载失败页、授权状态名。
- 模型侧文本：6 套人设预设的名称与内容、思考强度档位的名称与说明、时间上下文（`当前时间：` ↔ `Current time:`）、联网搜索上下文、`#todo` 抽取与压缩提示词（含 few-shot 示例）。
- 日期格式与 `Locale`：`M月d日 EEEE` ↔ `EEE, MMM d`。

**刻意不本地化**

| 内容 | 原因 |
|---|---|
| 语言下拉里的「简体中文」/「English」 | 语言名一律用该语言自身书写，英文读者找 `English` 比找「英语」容易。「跟随系统」这一项才随界面语言变 |
| `AppLanguage` / `ResolvedLanguage` 的 rawValue、`#todo` 前缀、`repeat` / `priority` 取值、`reasoning_effort` 的 `low/high/max` | 这些是**持久化数据与 API 字段**，不是文案。翻译它们会破坏已有配置与请求 |
| 系统默认提醒清单名、用户自己写的系统提示词、待办标题与备注正文 | 用户内容 |
| `#todo` 的日期解析（`parseDay` / `parseTime`） | 解析的是 ISO 格式 `YYYY-MM-DD` / `HH:MM`，与界面语言无关 |
| 「精确时间」关键词表 | 相反 —— 中英两套**都查**，刻意与界面语言解耦（误命中的代价只是缓存失效，漏命中的代价是答错时间） |

**已知缺口**

- 繁体中文（`zh-Hant`）没有独立译文表，回落简体。
- 系统授权弹窗里的权限用途说明写的是**中英并列**。授权框的本地化要走 `InfoPlist.strings`，也就是 `.lproj` 机制，与上面的技术选择冲突 —— 这是刻意保留的折中。
- `CFBundleDisplayName` 仍是中文（同样因为缺 `InfoPlist.strings`）。

## 新增一条文案

1. 在 `L10n.Key` 里加一个 case（命名 `<区域><用途>`，如 `todoCardTitle`）。
2. 在 `L10n.table` 里加条目，元组里**同时**填 `zh` 与 `en` —— 两个字符串写在同一个元组里，结构上不可能只填一种语言。
3. 调用处写 `L10n.t(.todoCardTitle)`；带参用 `L10n.t(.errorHTTP, code)`，模板占位符是标准 `%d` / `%@`。
4. 带计数且英文需要单复数时用 `L10n.count(.xxxOne, .xxxOther, n)`：英文按 `n == 1` 选单数、其余一律复数，中文两个模板填同一个串。
5. 跑 `./tools/selftest.sh`。它会拦住：漏填某个 Key、两语言出现空串、中英占位符数量对不上、英文表里残留中文。

也就是说，「改了中文忘了改英文」这类错误会在本地就暴露，不会流到界面上。

改**模型侧**文本时走 `Prompts.swift`：人设按 `PersonaDefinition`（id + 中英名称 + 中英内容）成组定义，同样是结构上不可能只填一半。

## 界面刷新是怎么触发的

文案取值是 `L10n.t(...)` 这种静态调用，SwiftUI 无法自行建立依赖，所以：

- `L10n` 是 `ObservableObject`，`ContentView` / `SettingsView` 各自 `@ObservedObject private var l10n = L10n.shared` 持有它。**持有即订阅** —— `resolved` 一变，整棵子树重绘。
- **AppKit 侧不会自动跟随**：菜单项文字与窗口标题是构建时的快照。`AppDelegate` 订阅 `L10n.shared.$resolved` 重建 `NSMenu`（`buildMenu()`）并同步设置窗口标题，状态栏图标的无障碍描述也一并刷新。
- 预设下拉的 selection 用**稳定的预设 id**，不是名称 —— 名称随语言变，拿名称当 tag 会让 selection 在切换后失配、下拉框显示成空白。

## 两个必须留意的坑

1. **系统提示词的默认值不能走 `@AppStorage`。** `@AppStorage` 的默认值只在属性包装器初始化时求值一次，而设置页是 `NSHostingView` 的根视图、只创建一次 —— 切语言后输入框会一直停在旧语言的默认人设上。所以 `SettingsView` 用 `Config.systemPrompt` 的 Binding（内部做「未设置 → 取当前语言默认值」）；用户一旦手改过，就固定成他自己的文本，不再跟随语言。
2. **预设反查必须跨语言。** `Config.presetID(for:)` 拿内容去匹配两种语言的所有预设：用户先选了中文预设、之后把界面切成英文，输入框里存的仍是中文原文 —— 只查当前语言会全部错显成「自定义」。自检里有专门的回归断言。

## 验证

逻辑层（166 项断言，其中 63 条 i18n 断言：键覆盖 / 空值 / 占位符数量 / 语言判定 / 英文表 CJK 漏译扫描 / 跨语言预设反查）：

```bash
./tools/selftest.sh
```

视觉层 —— 断言只能证明「字符串对」，证明不了「版面没被挤坏」。英文文案普遍比中文长：

```bash
./tools/i18n-snapshot/run.sh
# → /tmp/aqa-i18n-shots/settings-{zh-Hans,en}-{top,bottom}.png
```

它把设置页在两种语言下各渲染成「顶部 + 滚到底」两张 PNG，并自检窗口 frame 是否钉住、视图树里有没有滚动视图。

> 实测价值：英文的 `Open System Settings` 曾被中间那段说明文字挤成 `Open System S…` —— 纯断言完全看不出来，是这套快照抓到的，修法是给按钮加 `.fixedSize()`。
